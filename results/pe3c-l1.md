# PE3c: 識別子の取り出しを直して S3・S7 を測り直す（L1）

PE3b は、S3 と S7 の値が崩れた原因を「PE2d が『テストを除く』規則を質問の本文に書き、その定型の語を L1 の識別子の取り出しが拾うこと」に特定し、判断を 7 つ残した（[`pe3b-l1.md`](pe3b-l1.md) 第 6・10・11 節）。PE3c は統括の決定にしたがって次の 5 つを実施した。

1. 質問の定型を識別子から外す規則を入れる（PE3b の判断 #1 の (b)）。
2. 測定の記録に問題ファイルの版を持たせる（#6 の (b)）。
3. 影響を受けた問を測り直す（#5 の (b)）。
4. 系統の中の比較は共通の問だけで行い、「索引に無い種類が正解の問」を一律に外す（#2 の (b)、#4 の (b)）。
5. 修正後の値で L2 の代表の道具を決め直す（#3 の (b)）。

記録は [`pe3c-l1.jsonl`](pe3c-l1.jsonl)（測り直した S3・S7、1,386 回）と [`pe3b-l1.jsonl`](pe3b-l1.jsonl)（その他のシナリオ）、実装は [`l1/`](../l1/)。LLM は使っていない（例外は qmd で、qmd は問い合わせを自前のローカル LLM で展開してから検索する。道具の一部として使い、記録に残した）。事実と解釈は節を分ける。

**主な結果は 4 つ**ある。

1. 定型の 20 語を外すと **S3 の平均は 0.085 → 0.286、S7 は 0.047 → 0.120** に戻り、S7 の幅は 0.176 → 0.333、床は 22/36 → 17/36 になった。ast-grep と graphify の c3 の検索時間も PE3 の水準に戻った（第 3 節）。
2. 記録に問題ファイルの sha256 と識別子の規則が入り、**PE3b と PE3c を報告の値ではなく記録どうしで比べられる**ようになった。PE3b にできなかったことである（第 1.2・3.1 節）。
3. 「索引に無い種類が正解の問を外す」を**両向きに**当てはめると（コードだけを索引する道具の文書の問も、文書だけを索引する道具のコードの問も外す）、外れる対比は 462 件になる。外した問の平均はすべてちょうど 0.000 で、規則が広すぎないことが測定で確かめられた（第 4 節）。
4. L2 の代表は **グラフ系だけが codebase-memory-mcp → codegraph に変わり**、他の 6 つは変わらない。ただし codegraph は Markdown を索引しないので、L2 で文書の問を出すなら判断が要る（第 5・7 節）。

## 1. 直したこと

### 1.1 定型の識別子を外す規則（`l1/tasks.py`）

PE2d の決定「S7 の『テストを除く』をファイル名まで広げる」を反映して、S3 と S7 の質問の本文に除外規則が書き込まれ、除くファイル名の型がバッククォートで並んだ。L1 の識別子の取り出しは「バッククォートの中の識別子を現れた順に拾う」ので、その 20 語を毎回拾っていた。新しい規則は 1 行で書ける。

> **`BOILERPLATE_MIN_DOCS`（既定 10）問以上に現れる識別子は、質問の定型とみなして `ident`・`terms` から外す。**

この規則は**問題集合だけから機械的に決まる**（道具も測定結果も使わない）ので、そのまま事前登録に書ける。実装は `l1/tasks.py` の `boilerplate()`、根拠は `l1/tasks.py df`。判定は **L1 の全 284 問**で行い、`--scenarios` で絞っても変わらない（PE3b の診断では絞る前に数えていたが、規則としては明示が要る）。`ARE_L1_DROP_BOILERPLATE=0` で PE3b の取り出しに戻せる。

### 1.2 記録に問題ファイルの版を持たせる（`l1/run.py`・`harness/run.py`）

PE3b は前回（PE3）の記録を採点し直せなかった。問題が id ごと入れ替わっており、記録には問題ファイルの版が入っていなかったためである（`pe3b-l1.md` 第 3 節）。

- **L1**: 記録の 1 行ごとに `tasks` を入れる。`{file, sha256, n_l1, drop_boilerplate, min_docs, n_dropped, dropped_sha256}`。外した語の一覧そのものは `l1/run.py run` の最初の 1 行に出る。
- **L2**: `harness/run.py` の `meta.json` に `question_file`（その問が載っているファイル）と `question_versions`（`tasks/` の全 jsonl の sha256）を入れる。

今回の問題ファイルは `tasks/dev/pe2.jsonl`、sha256 `1bfc2266ea89dcffa0c7b5d5e32fdac5f509ec14f7bf18cb8d2e0a3ca7667709`、L1 の対象 284 問。

### 1.3 外す対比を索引の中身で決める（`l1/coverage.py`）

道具 × 題材 × **問**ごとに「正解のどのファイルも索引に無い種類か」を判定する。判定に使う索引の中身は当て推量ではなく数えた。第 4 節。

### 1.4 系統の中の比較（`l1/grade.py rep`）

同じ系統の 2 つを比べるときは、**両方が対比に使う問だけ**で、題材ごとの平均をさらに題材で等しく重みづけて比べる。PE3b が指摘した「外す規則が、索引しない道具を有利にする」を避けるため（判断 #2）。

## 2. 事実: 閾値の根拠（定型と本物の記号の分布）

`l1/tasks.py df`。「現れる問の数」は、その識別子が `ident` に現れる問の数。

**分布は 2 つに分かれる**。定型の 20 語はちょうど 35 問に現れ、本物の記号で最も多いものは 5 問（`Repo`）である。6〜34 には 1 語も無い。したがって閾値を 6 以上 35 以下のどこに置いても同じ 20 語が選ばれる。

| 閾値（この問数以上で定型） | 外れる語 | 識別子が変わる問 |
|---:|--:|--:|
| 2 | 29 | 50 |
| 3 | 22 | 41 |
| 4 | 21 | 38 |
| 5 | 21 | 38 |
| **6〜35** | **20** | **35** |
| 36 | 0 | 0 |

閾値 5 以下では `Repo` まで外れる（本物の記号なので外してはいけない）。**既定の 10 はこの平らな区間（6〜35）のほぼ中央**で、問題を少し足し引きしても選択が変わらない位置にある。

識別子の数への効き:

| | 変わる 35 問の `ident` の長さ（平均） | 識別子が空になる問 |
|---|--:|--:|
| PE3b（外さない） | 21.17 | 0 |
| PE3c（外す） | **1.17** | 0 |

変わるのは **S3 の 24 問と S7 の 11 問**（c1 9・c2 13・c3 13）だけで、いずれも識別子ありの問である。言い換えの問はバッククォートの識別子を持たないので変わらない。c4 の問は 1 つも変わらない。

## 4. 事実: 索引の中身と、外した対比

### 4.1 規則

> **正解のどのファイルも、その道具の索引に無い種類であるとき、その (道具, 題材, 問) の対比を外す。**

この実験の正解はコード（`.go`・`.ts`・`.tsx`・`.c`・`.h`）か Markdown（`.md`）のどちらかで、**両方が混ざった問は 1 つも無い**（284 問 = コード 188 問＋Markdown 96 問）。したがって規則は 2 つの事実で決まる。「索引に Markdown が入るか」と「索引に Markdown 以外が入るか」。どちらも索引を数えて決めた。

| 道具 | 題材 | 索引のファイル数 | うち .md | 判定 | 数え方 |
|---|---|--:|--:|---|---|
| global | c1 / c2 / c4 | 64 / 11,264 / 1,299 | **0 / 0 / 0** | Markdown が入らない | コンテナの中の `global -P` |
| semble | c1 / c2 / c4 | 1,198 / 192,343 / 7,379 | **0 / 0 / 0** | 同上 | `index/semble/*/index/chunks.json` |

## 5. 事実: L2 の代表の道具

規則（PE3 第 13 節、PE3c で第 4・1.4 節の扱いを当てる）: 候補は L0 で索引が作れた題材が 2 つ以上。**主の順序は開発用・主の条件の nDCG@10 を、両方が対比に使う共通の問で、題材ごとに等しく重みづけた平均**。同点（0.02 以内）は 1 回の検索の時間の中央値、次に L0 の索引の CPU 時間。標準・LSP・自作は候補が 1 つなので固定。

**PE3b で「判断が要る」とした 2 つは、どちらも決まった。**

1. **シンボル索引は ctags**。PE3b は「規則をそのまま読むと global」としたが、それは c4 の 0.000 が ctags の平均に入り global の平均から消えるためで、共通の問で比べれば PE3b の時点でも ctags が上だった。PE3c では差が 0.006 の同点で、同点の裁き（検索の時間 → 索引の CPU 時間）でも ctags になる。**どの読み方でも ctags** である。
2. **グラフ系は codegraph**。PE3b は「差の出どころは S3 の作り物なので、直してから決める」とした。直したあとも codegraph が codebase-memory-mcp を 0.082 上回る（S3 だけでなく S7 0.191 対 0.045、S4 0.469 対 0.170 でも上）。S3・S7 を外して当てると逆に codebase-memory-mcp が 0.435 対 0.402 で上になるが、**S3・S7 を外す理由はもう無い**（外す理由は「作り物だから」であり、作り物は直した）。

ただし codegraph には**選び方の外にある弱点**がある。Markdown を索引しないので、L2 で文書の問を出すと、グラフ系の条件だけが答えに届かない。codebase-memory-mcp は 4 題材すべてで文書も索引する。第 7 節 #2。

## 6. PE3 の進む条件

条件は「各シナリオで道具の間に差がある（順位の分散が 0 でない）」。

**7 つのシナリオすべてで条件を満たす。** PE3b が「辛うじて満たす」「形の上では満たす」とした S3・S7 も、いまは中身のある差になっている。

- S3 は幅 0.500・標準偏差 0.164 で、S1 に次いで道具の差が大きい。差の中身も変わった。PE3b では「複数の識別子をスコアで併合するか、順に引いてつなぐか」の差だったが、いまは記号索引（cscope 0.500・global 0.412・ctags 0.406）とグラフ（codegraph 0.449・graphify 0.432）が強く、全文検索（grep 0.188）が弱いという、**呼び出し関係を持つ索引かどうかの差**になっている。
- S7 は幅 0.333・床 17/36 で、PE3b の幅 0.176・床 22/36 より厚い。それでも 7 つの中ではいちばん薄い。床の 17 問のうち **15 問は言い換え**の問で、残り 2 問だけが識別子ありである（S3 の床 13 問はすべて言い換え）。つまり残る床は S7 固有のものではなく、統括の決定で本番に持ち込むと決めた「言い換えの床」である。

## 7. 判断が必要な点

| # | 論点 | 選択肢 | 推奨 |
|---|---|---|---|
| 1 | **閾値 10 は問数の絶対値**である。本番の問題は 350 問前後になる見込みで、定型の語が現れる問の割合（いまは 35/284 = 12%）が変わらなければ閾値 10 は安全だが、確かめてはいない | (a) 絶対値 10 のまま。(b) 割合（例: 全問の 3%）で書く。(c) **絶対値 10 のままにし、本番の問題を固めたときに `l1/tasks.py df` を出して平らな区間に 10 が入ることを確かめる**（入らなければ事前登録を出す前に直す） | **(c)**。規則は単純なほうがよく、確認は 1 コマンドで済む |

## 8. 再現の手順

```sh
export ARE_DATA=<題材と索引の置き場所>      # PE1 が作った indexes/ が要る

l1/tasks.py df                             # 定型の閾値の根拠（分布と閾値を動かした結果）
l1/tasks.py provenance                     # 問題ファイルの版と識別子の規則
l1/coverage.py count                       # 索引の中身（.md の件数）
l1/coverage.py rule                        # 規則が外す対比の一覧

l1/pe3c.sh                                 # S3・S7 を測り直す（1,386 回、1 時間 50 分）

# 以下は既定で pe3b-l1.jsonl に pe3c-l1.jsonl を重ねて読む
l1/grade.py verify                         # 記録の問い合わせがいまの規則と一致するか
l1/grade.py compare3b                      # PE3b と PE3c の記録どうしの比較（S3・S7）
l1/grade.py table                          # 道具 × シナリオ（nDCG@10）
l1/grade.py cells                          # 道具 × 題材
l1/grade.py applicability                  # 当てはまりと、外した対比の一覧
l1/grade.py docblind                       # 外した対比の平均が 0 であることの確認
l1/grade.py rep                            # L2 の代表の規則の当てはめ（共通の問での比較つき）
l1/grade.py spread                         # 進む条件
l1/grade.py time --include-na              # 時間と立ち上げ
l1/grade.py phrasing / querylang / xlang   # 表し方・質問の言語・多言語の副次の集計

# PE3b の取り出し（定型を外さない）に戻す
ARE_L1_DROP_BOILERPLATE=0 l1/run.py run --scenarios S3,S7 ...
```
